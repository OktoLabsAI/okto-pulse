## Notes

- `okto-pulse-core` was clean on `main` at start. `okto-pulse` had a pre-existing untracked `docs/pulse-simplification/IMPLEMENTATION_LEDGER.md`; leave it intact.
- The legacy unrelated-board fencing test remains valid for the old adapter default; Community runtime enables the durable protocol. The native Spec test pauses graph commit while a different Board commits to the same SQLite database in under 10 seconds (test threshold); it then verifies normal completion.
- Native Grafx receipt test passed after closing and reopening the graph. Provenance refusal test passed when commit history is unavailable. Core and Community changed interfaces compile.
- SQLite writer diagnostics now start timing at explicit `BEGIN IMMEDIATE`, before the request's first DML. The event reports commit/rollback requested; it is a lower bound, not a proof of durable completion.
- An exact current SQLite schema fingerprint rejects ad-hoc table additions; any new table requires a governed schema conversion or a journal outside the source database. The existing queue is already source-transactional.
- Validation: Community focused worker/Grafx/lock suite 101 passed; routed graph transaction suite 11 passed; Board erasure 4 passed; routed lifecycle and worker runners 34 passed; native Spec journal, unrelated SQLite writer, and post-commit recovery integration 1 passed. Core directly affected suite 27 passed; worker run-loop and resilience suite 28 passed. Both 0.4.1 wheels rebuilt after the final adapter changes. The application suites used the matching 0.4.1 wheel metadata on the pytest path because the local Python environment still advertises a different installed pair.
- An unrelated pre-existing Core test expects an exact rebuild source set without `sprint`; another uses a plain `object()` as a DB for a source path requiring `get()`. These fail in the selected Core suite and are not caused by this protocol.
- Community release-gate tests: 6 passed, 1 external gate could not run because neither `OKTO_E2E_GRAFX_WHEEL` nor `OKTO_E2E_GRAFX_REPO` was configured. Individual Core/Community 0.4.1 wheels built successfully.
- The persistent kernel rendezvous sits outside the board directory so Windows board erasure can remove the graph directory while the guard is held; direct test passed.
- The native integration injects an exception after Grafx commit but before SQLite ACK and verifies recovery with the actual audit adapter. A separate native receipt test verifies reopen. These tests do not simulate a physical power cut or measure throughput on the reported 570 KB Spec workload.
- Rollout requires all 0.4.0 processes to stop before starting the paired 0.4.1 Core and Community distributions. Old workers do not understand the journal, so mixed-version workers must not share a live database. The existing distribution compatibility gate checks the paired versions within one process; it cannot fence a separate old process.
- Implementation choice relative to the initial plan: the existing transactional queue supplies source intent and claim lineage; the append-only `domain_events` table supplies the operation journal, avoiding a physical schema conversion. The native Grafx commit-history metadata supplies the graph receipt. The plan's separate desired/applied revision columns and explicit cross-process protocol epoch were not added. Further source-invalidation coverage and a production workload latency benchmark remain follow-up work.
