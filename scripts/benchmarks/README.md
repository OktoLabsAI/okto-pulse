# Disposable native delivery measurement

`test_native_delivery.py` executes authenticated delivery evidence recording,
exact replay and a new client session against the current contract. It uses
this checkout's current test helpers and creates a disposable SQLite database.
It does not import an old base or qualify the full initiative benchmark.

Prove source/wheel/install byte equality first. In PowerShell, set `PYTHONPATH`
to Core `src` followed by Community `src`, separated by `;`. Use the qualified
interpreter and new output, temporary database and report paths for each run:

```text
rtk proxy <python> -X utf8 <community>/scripts/measure_mcp_fixture.py <new-output-dir> <community>/scripts/benchmarks/test_native_delivery.py --confcutdir=<community>/scripts/benchmarks -q -x --basetemp=<new-temp-dir> --junitxml=<new-report.xml>
```

The collector records imported package origins, actual SQL request windows,
discovered tool pages and resources read. Payloads and credentials in this test
are synthetic. Do not use the collector with production data or credentials.
Setup, authorship and external implementation are outside this segment.
`cl100k_base` token counts are reproducible estimates, not model billing.

Previous comparative receipts in the Core implementation ledger are historical
observations of their recorded commits, not evidence for the current clean-break
build. C4 still requires qualification of the applicable integrated scenarios;
a passing segment alone proves neither full-flow savings nor final delivery.
